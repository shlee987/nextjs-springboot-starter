### 파일 기능의 승인된 실제 실행 확인

기존 검증용 JDBC DB에 core V2를 적용하고 재실행 시 중복 적용되지 않음을 확인했다. 기본 IDE DB·기존 사용자 서버·Redis·컨테이너는 초기화하지 않았다. 별도 저장 루트와 A/B 서버에서 PNG/JPEG 저장·메타데이터 제거·한글 이름·서버 간 목록/다운로드·소유자 분리·HEAD·삭제를 확인했다. 소유자 용량 경쟁은201/409로 한 건만 허용됐으며, 전용 fixture의 실제 SQL 롤백·디스크 저장 실패 보상·삭제 실패 후 재시도도 확인했다.

실제 검사에서 쿠키 JWT가 Resource Server의 기본 CSRF 예외로 처리되는 결함을 발견해 수정했다. 수정본에서 정상·잘못된·만료 형태 access 쿠키의 CSRF 누락/오류63개 조합과 Origin 오류3건은403이며 정상 인증·갱신·파일 처리는 유지됐다. 이 사실은 Origin 검사를 CSRF 검사 대신 사용해도 된다는 뜻이 아니다. 상세 구성 기준은 [인증 설계](authentication-foundation.md)를 따른다.

백엔드 시험이 만든 파일28개는 생성 목록에 따라 API로 삭제하고 해당 메타데이터 제거와 성공 감사를 대조했다. 롤백 시험 두 건에는 파일 행과 성공 감사가 남지 않았다. 새 테이블·Flyway 이력·전용 루트는 보존했고, 프론트가 별도로 만든 검수 파일은 일괄 삭제하지 않았다. 최종 잔류량과 프론트 생성 파일의 정리는 모듈 검증 기록에서 별도로 확인한다. 실제 운영 저장소·다중 호스트 파일 공유·시스템 중간 단절 및 불명확 commit 전체를 검증한 결과로 확대하지 않는다.

### 마감 리뷰에서 보완한 사항

파일 HEAD 응답의 스트림 해제, 날짜 외부 값 변경 후 부모 검증 오류 동기화, 파일 오류 코드와 진단 ID 유지, Unicode 파일명 길이 기준을 수정하고 독립 재검토했다. 실제 파일 검사에서 발견한 쿠키 JWT CSRF 예외도 수정·실HTTP 검사·독립 재리뷰로 해소했다. 로컬 기본 저장 경로는 빌드 폴더 밖의 .private/files이며 설정·환경 예시·실행 문서를 맞췄다. 프론트 브라우저 검수의 실제 확인과 도구 한계는 아래 기록에서 구분한다. 날짜·오류 코드·파일명·로그아웃 경계의 발견 사항은 최종 코드 재리뷰에서 해소됐다.

## 추가 통합 재점검 (2026-10-30)

여러 차례의 수정이 합쳐진 최종 소스를 기준으로 POST-CLOSE-R1 독립 읽기 전용 점검을 수행했다. 새 finding이나 마감을 막는 코드·설정·문서 불일치는 없었으며 이번 범위는 마감 가능으로 판정했다.
