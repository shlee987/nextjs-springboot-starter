# 공통 컨트롤 보완 설계와 선택 후보

2026-10-30 공식 UI 문서와 실제 공통 컨트롤을 비교해 정리했다. 이후 사용자가 UIOPT01~09 구현과 라디오 표시 확대를 승인했다. 구현과 예제·검증은 [UI 옵션 기록](../../frontend/UI-OPTIONS.md)을 따른다. 아래 별도 선택 후보는 승인된 기본 범위와 구분한다.

## 먼저 확인한 점

버튼·입력·체크박스·라디오·스위치·단일/검색/복수 선택·폼·팝업·알림·탭·검색/페이지·그리드·차트는 공통 구현이 있다. 날짜 선택기도 공통 구현에 포함한다. 유명 UI 라이브러리의 전체 목록을 복제할 필요는 없다. 자주 쓰는 옵션과 상태를 빠짐없이 표현하는 쪽이 현재 프로젝트 목적에 맞는다.

Radix는 기본 동작·키보드·포커스, Bootstrap은 폼 배치와 크기 체계, Ant Design은 업무용 선택/목록의 옵션, MUI는 자동완성의 비동기 처리, WAI APG는 달력의 접근성 동작을 참고했다. 아래 추천은 이 자료와 현재 코드의 차이를 보고 설계자가 판단한 것이다. 해당 라이브러리를 모두 설치하자는 제안은 아니다.

## 1. 기존 컨트롤에서 먼저 보완할 옵션

| 번호 | 대상 | 조사 당시 확인한 내용 | 적용한 보완 방향과 사용 예 |
| --- | --- | --- | --- |
| UIOPT01 | Select | 크기·비활성·로딩·선택 해제·폼 속성은 있지만 기본 안내 문구가 고정돼 있다. | placeholder/빈 결과 문구, 충분한 팝업 높이와 스크롤, 긴 항목 표시를 공통 옵션으로 정리한다. “부서를 선택하세요”, “선택할 부서가 없습니다”처럼 용도에 맞게 안내한다. 항목 그룹은 실제 필요 화면에서 추가한다. |
| UIOPT02 | 검색형 Select | 현재 검색은 전달받은 배열을 내부에서 필터링한다. 서버 검색을 제어하는 입력/실패/재시도 옵션은 없다. | 검색 중·검색 전·검색 결과 없음·불러오기 실패를 구분한다. 직원/거래처처럼 서버 검색이 필요한 경우에만 입력 이벤트·요청 취소·최신 응답 유지·최소 글자 수·입력 대기 시간을 추가한다. 이미 가진 배열을 검색하는 모드와 분리한다. |
| UIOPT03 | 복수 선택 | 검색·선택·비활성·전체 해제는 있으나 선택 요약과 최대 선택 수는 없다. | “3개 선택됨”, 선택 항목 태그와 개별 해제, 최대 선택 개수, 적용 범위가 분명한 전체 선택을 검토한다. 검색 결과 전체인지 전체 데이터인지 버튼에 표시하고, 로드하지 않은 서버 데이터를 모두 선택했다고 표시하지 않는다. |
| UIOPT04 | Checkbox | 공통 checked 타입이 boolean이며 일부 선택 상태는 제공하지 않는다. | 전체 선택 체크박스에 `indeterminate`를 추가한다. 10개 중3개 선택된 경우 빈칸이나 체크 대신 가로선으로 표시한다. 기존 boolean 사용 코드는 유지한다. |
| UIOPT05 | 입력/FormField | 기본 HTML 속성·도움말·오류·지우기·암호 표시를 제공한다. | 자주 쓰는 앞/뒤 단위, 글자 수 표시, 여러 줄 입력의 적절한 자동 높이를 검토한다. 오류가 여러 개면 상단 요약에서 해당 입력으로 이동할 수 있게 한다. 앞/뒤 아이콘·지우기·로딩이 동시에 있을 때도 글자와 포커스가 겹치지 않아야 한다. |
| UIOPT06 | 날짜/시간 선택 | 현재 공통 달력과 키보드 조작을 추가하는 중이다. | 이번 구현의 월/연도 이동·직접 입력·최소/최대·선택/오늘 구분·읽기 전용·확인/취소를 먼저 완성한다. 주말/휴일 등 특정 날짜 선택 제한, 시간 단위, 자주 쓰는 기간은 다음 확장 후보다. 기존 UTC·밀리초·엄격 검증은 유지한다. |
| UIOPT07 | 확인 대화상자 | 현재 busy와 확인 콜백을 외부에서 제어한다. 기본 확인 버튼은 위험 스타일이다. | 동작에 맞는 확인 문구/강조색, 취소/확인 순서, 처리 실패 시 내용 유지·안전한 오류 표시를 검토한다. 삭제가 아닌 “선택 적용”까지 모두 빨간 확인 버튼으로 만들지 않는다. 비동기 성공 뒤 닫기와 실패 뒤 유지의 예제를 제공한다. |
| UIOPT08 | 로딩/알림/상태 | Spinner·Skeleton·Toast·빈 결과·오류 컴포넌트가 있다. | 빈 결과에 “조건 초기화” 등 실제 다음 행동을 제공하고, 오류에는 선택적 재시도·진단 ID를 일관되게 표시한다. 버튼/행/페이지 로딩의 크기와 안내를 구분한다. Toast 동작 버튼이 필요하면 닫기와 겹치지 않게 배치한다. |
| UIOPT09 | 작업별 중복 실행 방지 | 사용자와 추가 방향을 정했다. API 호출이 원래 비동기인지와 별개로, 실행 중 같은 작업이 다시 시작되지 않도록 공통 관리한다. | `사용자저장:100`처럼 작업을 구분하는 고정 키를 사용한다. 첫 실행에서 즉시 잠그고 처리 중 같은 키의 추가 실행은 무시한다. 성공·실패·취소 등 작업 종료 시 잠금을 해제하며 버튼 로딩·비활성화와 연동한다. 같은 작업을 실행하는 여러 버튼은 키를 공유하고 다른 작업은 병렬 실행할 수 있게 한다. |

UIOPT01·04·07은 작은 변경으로 재사용성이 좋아질 후보이고,02의 서버 검색은 통신 상태까지 설계해야 해서 단순 스타일 옵션보다 작업량이 크다. 여러 옵션을 한 번에 기본값으로 켜지 않는다.

### UIOPT09: 작업별 중복 실행 방지

2026-10-30 처음에는 개선 목록으로 기록했고, 이후 사용자가 구현을 승인했다. 현재 구현과 예제·시험 결과는 [UI 옵션 기록](../../frontend/UI-OPTIONS.md)의 UIOPT09를 따른다.

- 매 클릭마다 새로 만드는 요청 ID가 아니라, 같은 작업을 식별하는 키를 사용한다. 예: `사용자저장:100`.
- 첫 실행에서 화면 상태 갱신을 기다리지 않고 즉시 잠근다. 처리 중 재실행을 대기열에 쌓지 않고 무시한다.
- 키를 공유한 버튼은 로딩·비활성 상태도 함께 반영한다. 실제 작업이 종료되면 성공·실패 여부와 관계없이 잠금을 정리한다.
- 다른 작업 키는 병렬 실행을 허용한다. 전체 API를 하나의 잠금으로 막지 않는다. 키에 비밀번호·토큰·개인정보 본문을 넣지 않는다.
- 검색의 최신 결과 유지나 연속 저장이 필요한 흐름은 별도 정책으로 둔다. 고정 시간의 debounce와 작업 완료까지의 중복 방지를 혼동하지 않는다.
- 현재 브라우저 실행 범위의 보호이며 여러 탭·다른 클라이언트·네트워크 재시도에 대한 서버의 중복 처리 보장을 대신하지 않는다.
- 예제와 검수에는 빠른 연속 클릭, 같은 키를 공유하는 두 버튼, 다른 키의 병렬 실행, 실패 후 재실행, 동기 예외 뒤 잠금 해제를 포함한다.

Breadcrumb·분리선·팝오버 같은 구조는 이미 화면/기존 도구 안에 일부 존재한다. 단순히 공통 export 이름이 없다는 이유로 새 기능이 빠졌다고 보지 않는다. 리치 에디터·캐러셀·별점·전체 UI 프레임워크 교체는 이번 기본 묶음의 우선순위가 아니다.

## 3. 모든 컨트롤에 공통으로 확인할 내용

옵션 수보다 중요한 것은 각 상태의 기본 품질이다.

- 값 없음·입력 중·값 있음·지우기·검증 오류·읽기 전용·비활성·로딩을 구분한다.
- 마우스뿐 아니라 Tab/Shift+Tab·Enter/Space·방향키·Escape를 각 컨트롤 의미에 맞게 확인한다. 팝업을 닫으면 시작한 조작 요소로 돌아온다.
- label·도움말·오류 연결을 유지한다. placeholder만으로 입력의 목적을 설명하지 않는다.
- 로딩 전후에도 글자 중앙·아이콘 간격·버튼 크기가 불필요하게 흔들리지 않는다. `loading=false`에 빈 아이콘 공간이 남아 글자를 미는 문제 같은 항목을 직접 확인한다.
- 긴 한글/영문·긴 선택값·빈 결과·한 개/많은 항목과 PC/모바일의 열린 상태를 확인한다. 스크롤은 필요한 구역 안에서만 생긴다.
- 값·콜백·ref/onBlur·폼 연동 방식을 기존 컴포넌트와 일관되게 한다. 모든 컴포넌트에 모든 옵션을 억지로 넣지는 않는다.
- 새 옵션마다 사용 예제·사용 상황·예상 결과를 함께 제공한다. 실제 구현과 예제가 없는 prop 이름만 늘리지 않는다.

## 4. 적용 범위와 이후 후보

1. UIREF01~19의 색상·간격·라디오·검색 빈 결과·데이트피커·버튼 중앙 정렬을 구현하고 PC·모바일 화면을 검수했다. 실제 확대·도구 제한은 UI 검수 기록에 남긴다.
2. UIOPT01~09의 Select 문구/상태, 일부 선택 체크박스, 복수 선택 요약·태그, 입력/확인창 옵션과 작업별 중복 실행 방지를 구현했다. 초기 조사 표의 미비 내용은 당시 상태이며 현재 미구현 목록이 아니다.
3. 서버 검색은 제어된 예제로 상태·취소·최신 응답을 확인하며 실제 검색 API를 새로 만들지 않았다. 트리·단계·장시간 진행 작업은 이후 선택이다. 파일 업로드는 별도로 승인되어 실제 API와 연결했고 파일 설계·검증 기록을 따른다.

초기 조사는 제안 단계였으며, 아래 착수 확정 절에서 UIOPT01~09를 승인 범위로 정했다. TreeSelect·Stepper 등 별도 선택 후보는 실제 사용 흐름이 정해진 뒤 추가한다. 파일 업로드는 이후 별도로 승인되어 [파일 설계](attack-defense-and-files.md)에서 관리한다.

2026-10-30 아래 공식 문서의 기능·속성·사용 예를 확인했다. 설명을 이해하기 쉽게 요약했으며 원문 전체의 복사본은 아니다.

- [Ant Design Select](https://ant.design/components/select/): 검색·선택 그룹·여러 항목·선택 개수·로딩 옵션
- [MUI Autocomplete](https://mui.com/material-ui/react-autocomplete/): 열 때 불러오기와 입력 중 서버 검색
- [WAI APG Date Picker](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/): 달력 포커스·키보드 조작. 예제 코드의 그대로 복사나 모든 환경 지원 보장을 뜻하지 않는다.

## 2026-10-30 개선 작업 착수 확정

사용자가 “라디오 안에 선택 표시되는 동그라미 살짝만 더 컸으면 좋겠어. 여기까지 내용 취합해서 개선작업 진행해줘”라고 요청했다. 앞의 조사 단계·목록만 추가한다는 안내는 아래 확정 범위에 대해 대체한다.

- UIOPT01~09의 기존 컨트롤 보완을 구현한다. Select의 용도별 문구·긴 항목·목록 스크롤, 검색형 Select의 상태 구분, 복수 선택 요약·개별 해제 태그·최대 선택 수, Checkbox 일부 선택 상태, 입력 단위·글자 수·Textarea 자동 높이·폼 오류 요약/이동, 날짜/시간 컨트롤 완성, 확인창 문구·의도·비동기 실패 유지, 상태 안내·선택적 재시도, 작업별 중복 실행 방지를 포함한다. 실제 적용 가능한 화면/예제에서 사용하고 설명한다. 중복된 기존 기능은 새로 만들지 않는다.
- 라디오 안쪽 선택 원은 현재 실측 크기에서 약 2px 키우는 방향으로 조정한다. 바깥 테두리·안쪽 원 사이 여백이 남아 라디오 형태가 분명해야 한다. PC/모바일·선택/포커스/disabled를 확인한다.
- 작업별 중복 실행 방지는 동일 키의 즉시 잠금·추가 실행 무시·여러 버튼의 상태 공유·완료 후 해제와 로딩 연동을 제공한다. 재렌더 전 연속 호출도 막으며 사용자/화면 전환 시 키 충돌·오래된 완료에 의한 새 잠금 해제를 방지한다. Promise 반환과 실패 처리 방식을 명확히 하고 기존 오류·토스트·인증 재시도 흐름을 손상하지 않는다. 변경 요청의 자동 재시도나 서버 중복 처리 보장을 새로 추가하지 않는다.
- 검색형 Select의 서버 검색 제어는 공통 옵션과 제어된 예제로 확인할 수 있지만 새 서버 검색 API를 만들지 않는다. 선택 전체의 범위는 분명히 표시한다. 기존 UTC·정밀 숫자·폼 연동·접근성·CSP는 유지한다.
- TreeSelect·Stepper·파일 업로드·독립적인 장시간 진행 작업은 여전히 업무 흐름이 정해진 뒤의 후보로 남긴다. 불필요한 새 라이브러리나 백엔드 변경을 추가하지 않는다. 특정 날짜 제한·시간 간격·빠른 기간은 현재 날짜 예제에서 자연스럽게 쓸 수 있는 범위만 반영한다.
- UIREF15~19 및 제출 버튼 중앙 정렬 수정은 보존한다. 전체 화면을 PC/모바일에서 직접 확인해 문구 잘림·중앙 정렬·아이콘/로딩 간격·상태별 배치·열린 팝업을 검수한다. 실제 확인과 미확인을 구분하여 완료 보고한다.
