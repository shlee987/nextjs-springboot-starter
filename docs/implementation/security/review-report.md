# 공통 보안 기준 검토 결과

검토 버전: 0.2 / 검토일: 2026-10-22 / 결론: 기술 선택 전에 가능한 공통 보안 기준의 조사·대조·문서 정합성 검토 완료.

## 완료 범위

- 공통 보안 guide·references·setup-checklist와 기존 영역별 설계를 대조했다.
- OWASP ASVS 5.0.0 공식 tag의 V1~V17 본문 17개, 요구사항 345개를 읽고 분류·설계 연결했다. L1 70개, L2 183개, L3 92개다. L2 검토 대상은 누적 L1+L2 253개다.
- [조항 대조표](asvs-mapping.md)에 모든 ID·레벨·기본/조건부/결정후/선택강화·관련 설계·검증을 남겼다. 본문을 복제하지 않았다.
- [보완 통제](controls.md) GOV01~GOV15와 시험 V23~V36을 추가했다.
- WSTG 4.2의 CSRF·IDOR·업무 시간 관련 시험 본문을 확인해 검증 시나리오를 구체화했다. WSTG 전체 시험 실행·전문 대조를 뜻하지 않는다.
- NIST SP 800-204D의 §5.1~5.2 본문을 확인해 빌드 증거·권한·artifact 검증을 보강했다.
- 링크·요구사항 식별자·본문 추출 조항 개수와 중복을 기계적으로 검사하고, 정책의 주요 충돌은 아래와 같이 검토했다.

## 남은 항목의 경계

지금 수행할 일반 보안 기준 조사·누락 대조는 이 검토로 닫는다. 아래는 “나중에 조사할 일반 항목”이 아니라 선택한 구성을 구현하기 위한 다음 단계다.

| 관문 | 이후 확정할 것 |
| --- | --- |
| D01 | 제품 버전별 함수/속성명·라이브러리 호환성·지원기간 |
| D04/D09 | 실제 인증 수단·MFA/복구·역할/필드 표·API 계약 |
| D05/D06 | DB·TLS·프록시·OS 제품별 설정 키·CIS benchmark 판/profile |
| D07 | 실제 검사 도구·명령·rule·필수 check·배포 provenance 기능 |
| D08 | 채택한 조건부 기능의 구체 명세·시험. 미채택이면 미사용 증거 |
| D10 | 실제 데이터와 규제·보존기간·RPO/RTO·운영 담당 |

CIS 제품별 benchmark와 미선택 IIS/Windows/SQL Server/Jenkins 세부 설정은 현시점 대상이 아니다. 선택 없이 임의 설정을 만드는 것으로 완료를 꾸미지 않는다.

NSA/CISA PDF는 공식 원문 직접 접근이 403으로 거부되어 색인된 일부 본문만 확인했다. 본문 전체 확인 자료로 승격하지 않았고, 현재 필수 요구사항의 유일 근거로 사용하지 않는다. 중복되는 통제는 확인 가능한 ASVS·OWASP·NIST 본문으로 근거를 확보했다. 해당 가이드 전체 준수 목표를 채택할 경우 별도 전문 확인이 필요하다.

## 완료와 검증의 의미

지금 완료는 공통 보안 설계 기준의 조사·분류·검토다. 애플리케이션 코드·서버·CI·DB를 만들거나 보안 시험을 실행하지 않았다. ASVS 인증, 전체 L2 충족, 모든 취약점 제거, WSTG 전체 통과를 선언하지 않는다.

구현자는 [시작 문서](../README.md) → [결정 관문](../decisions.md) → 담당 영역·controls → [검증](verification.md)을 사용한다. 일상 작업 중 같은 원문을 반복 조회할 필요는 없다. 새 버전·기능·보안 권고·불일치가 생기면 해당 ID만 갱신한다.

원본 공통 지침은 변경하지 않았다. 이번 보완은 프로젝트 설계에만 반영했다.
