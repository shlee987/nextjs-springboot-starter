# 프론트 전체 UI 정리·반응형 적용 설계

기준일: 2026-10-29 / 상태: 사용자 방향 확정·이번 변경 구현 지시 기준.

> 설명 문구와 예제 안내는 [자연스러운 설명 작성 기준](readability-and-local-logs.md)의 1절을 함께 적용한다. 작업 순서나 기술 조건을 바꾸지 않고 문장을 짧고 이해하기 쉽게 정리한다.

## 1. 목표·적용 경계

사용자는 개별 화면의 임시 보정보다 전체 화면의 어색한 정렬·간격·글꼴·컨트롤 혼재·설명 부족을 먼저 정리하고 이후 디자인을 조금씩 조정하기로 했다. 별도 시안 승인 관문 없이 밝고 단정한 기본형으로 진행한다. PC와 모바일 모두 각 환경에 맞게 보여야 하며 단순 축소/전체 세로 쌓기로 처리하지 않는다.

[기존 기능 계약](frontend-foundation.md)의 LIB/UI/EX/FV 전체 범위·경로·기능을 유지하고 표현/공통 컨트롤 적용을 개선한다. 변경 범위는 frontend/**, 이 문서는 설계 담당 소유다. backend/infra/API·인증 정책·범용 common-rules는 변경하지 않는다. Bootstrap의 배치/폼 패턴을 참고하되 Bootstrap/Tailwind/새 UI·아이콘·테스트 플랫폼을 설치하지 않는다. 기존 Radix Primitives·CSS Modules·CSS variables와 공통 컴포넌트를 확장한다.

## 2. 공통 시각 기준

- UIREF01 글꼴: Pretendard를 한글·영문 기본으로 자체 제공한다. 공식 배포의 고정 릴리스 WOFF2와 필요한 굵기400/500/600/700만 제공(지원 변수 파일이면1개 사용 가능), 원본 출처·버전과 SIL OFL1.1 고지를 frontend에 포함한다. CDN/runtime 외부 폰트 요청·브라우저별 system-ui만 의존하지 않는다. font-display:swap과 읽기 가능한 sans-serif fallback을 둔다. 코드만 monospace. 실제 폰트 로드와 적용을 브라우저에서 확인한다.
- UIREF02 글꼴 크기/행간: 기본 본문15px/1.5, 보조13~14px/1.5, 표14px, 페이지제목26px/1.3, 구역제목18px/1.4를 토큰화한다. 모바일 본문·일반 입력은16px을 기본으로 하며 라벨/버튼은 명시 행간을 사용한다. 제목/영문에 과한 자간·굵기/세리프 혼용 금지. 200%확대에서 텍스트를 잘라 규격을 맞추지 않는다.
- UIREF03 색/위계: 연한 중성 배경·흰 표면·짙은 중성 본문·차분한 청색 주동작으로 정리한다. 현재 토큰을 정비하고 화면별 임의 팔레트 금지. 일반/보조 버튼은 중성 outline/soft, 주요 버튼만 청색, 위험은 의미 있는 동작에만 사용. 기본/hover/active/focus/disabled/loading을 구분하고 색만으로 의미 전달 금지. 정상 본문 대비4.5:1, 큰 글자3:1과 비문자 경계/상태의 가시성 확인. 색을 밝히기 위해 흰 글자 대비를 희생하지 않는다.
- UIREF04 간격/크기: 기본4px 스케일(4/8/12/16/24/32), 페이지 여백 PC24~32/좁은화면16, 섹션24, 관련 묶음16, label-control6~8, 아이콘/텍스트8. margin-bottom과 부모gap 이중 적용을 제거한다. PC 일반 입력/버튼40px, 조밀한 도구모음32px, 모바일 주요 터치44px. 같은 행 규격 일치. 고정 높이로 확대/긴 글자를 자르지 않는다.
- UIREF05 아이콘/표시: check/radio/directional/close를 문자 ✓●⌄×의 글꼴 위치에 의존하지 않고 기존 SVG 방식/CSS 도형으로16/20px 규격화한다. label/control·아이콘/text의 수평/수직 정렬·disabled를 공통화. SVG는 display:block, decorative는aria-hidden, 아이콘 버튼은 accessible name과 최소24px 조작영역(터치44px 권장).

## 3. PC·모바일·중간 화면

- UIREF06 전역 프레임: PC는 약240px 분류 사이드바+가변 본문, 모바일은 메뉴 열기/닫기와 overlay drawer·Escape/focus 복귀·내부scroll. 992px부터 PC sidebar 기본, 이하 drawer 기본으로 설계하되 실제 내용 폭 기준으로 검수한다. 전체 본문 max-width 약1440px, 폼은약640~720px로 별도 제한한다. 검색·표는 가능한 본문 폭을 활용하고 긴 입력1개로 화면 전체를 채우지 않는다.
- UIREF07 배치: 576/768/992/1200px을 참고 경계로 사용한다. 최소320px에서도 문서 전체 가로 스크롤/컨트롤 잘림 없음. 콘텐츠 유효폭이 좁으면 sidebar가 있어도 열 수를 줄인다. 목차는 본문 유효폭에 맞춰 최소카드240px로1~3열, 관련 입력은 넓을 때2열/좁을 때1열, 검색은 관련조건과 actions를 행 끝 기준 정렬 후 줄바꿈한다. DOM 읽기/Tab 순서와 화면 배치 순서를 일치시킨다.
- UIREF08 테이블/팝업: 그리드는 의도된 내부 가로scroll만 허용, 검색·정렬·건수·페이지는 화면안에 유지. 모바일에서 모든 열을 강제로 압축하거나 데이터 비교 의미를 잃는 카드로 일괄변환하지 않는다. 팝업은 viewport여백16이상·max-height/내부scroll, 긴내용에서도header/close/action접근가능. toast는PC우하단/좁을때화면여백16, 겹침/가림/넘침 확인. 화면 회전/200%확대시 drawer/top offset을 고정 header높이 추측으로 맞추지 않는다.

## 4. 공통 컨트롤 적용과 실제 결함 수정

- UIREF09 모든 select 적용: 현재 Select/Combobox가 있음에도 Search의페이지크기·목록정렬 등에 원시select를 직접 사용한 혼재를 전수 점검한다. 기본 단일선택은 기존 공통Select, 많은항목 검색은Combobox, 복수는MultiSelect로 통합한다. 필요 variant/size/width/ref/label/error속성은 기존공통API에 추가하고 각 화면별 새 구현 금지. 기능/필수옵션/허용값/키보드/폼ref·onBlur를 보존한다. 네이티브태그는 공통컨트롤 내부의 구현수단으로 사용가능하며 모든 HTML을 제거한다는 뜻은 아니다. 화면/예제 직접button/input/select/checkbox도 전수 조사해 공통컴포넌트로 교체하거나 의미상 예외를 기록한다.
- UIREF10 입력그룹: input flex:1/min-width:0, 부속button flex-shrink:0/white-space:nowrap/규격일치. 지우기·암호표시가 한 글자씩줄바꿈되거나 입력보다 커지지 않는다. fieldset/legend/dd/nativebutton의 브라우저기본여백/테두리가 의도없이 남지 않게 역할별reset한다. 검색옵션은 세로100% 목록·일정높이·선택표시/hover/focus/disabled, footer actions는목록과구분. select의값왼쪽·chevron오른쪽중앙·긴값ellipsis와accessible명 유지. arrow/accordion아이콘의기준선통일.
- UIREF11 알림/상태: Toast/InlineAlert 본문·상태아이콘·우상단닫기X·선택action영역을 분리. 닫기와본문을 inline으로붙이지않음. 긴본문은close공간침범없이wrap, retry/action은하단 또는별도우측영역. dismissible정책·aria-live/중복방지/timeout/키보드동작유지. 조회전안내와검색패널사이16~24px, error/empty/loading의공통높이/여백체계.
- UIREF12 목록/프로필: 검색패널→결과toolbar(건수/정렬/size)→grid→pager 순서와 시작선 정렬. 도구모음은flexwrap/간격12~16. 프로필은 label/value 정렬(PC2열grid/모바일1열), 중복이름/아이디/부서제거, 기본정보/소속·권한/계정동작구분. 긴permission은badge/줄바꿈목록, 원본값/의미유지하고 가로로끝없이밀지않는다. 날짜 표시 형식과 UTC/서울 계약은 변경하지 않는다.

## 5. 목차·예제 전달 방식

- UIREF13 목차/메뉴: 입력과선택·피드백과탐색·데이터표현·실서비스연결 등4분류로정돈, 각카드는 기능이름+고유한한줄용도+이동표시. 모든카드에동일한'합성예제/검증진행'반복금지. sidebar도동일한원본분류/권한/현재메뉴를사용한다. 서비스메뉴권한필터와shared예제off/직접404계약유지. 오래된'API준비전/승인필요'일괄문구는현재실행조건설명으로바꾸되 운영/미검증 성공을 주장하지않는다.

## 7. 사용자 재점검 후 추가 수정 (2026-10-30)

이번 추가 수정은 사용자가 화면 두 장과 함께 다시 점검하고 작업하라고 요청한 사항이다. 색상·간격·선택 표시가 실제로 달라졌는지 실행 화면에서 확인한다. 예전 UIREF01~14 결과와 별도 항목으로 기록한다.

### UIREF15 — 탁한 강조색을 선명하게 바꾼다

현재 primary #2356cb, danger #b8273b, success #14694e가 유지돼 사용자가 요청한 색감 변화가 충분히 반영되지 않았다. 청색은 #2563eb, 적색은 #e11d48을 기본 후보로 사용한다. 녹색도 같은 수준으로 선명한 색을 선택한다. 예를 들어 #008744를 후보로 검토할 수 있다. 버튼·알림·배지·체크·링크 등의 관련 토큰을 함께 정리한다. 기본/hover/pressed/soft/text 조합을 실제로 확인하고, 채도를 올린 색 위에 무조건 흰 글자를 얹지 않는다. 정상 크기 텍스트 대비4.5:1을 계산하고 필요하면 글자색과 배경을 조정한다. 오류/성공은 색과 함께 문구·아이콘으로 구분한다. 색만 후보로 문서에 남기고 실제 토큰을 그대로 두지 않는다.

### UIREF16 — 모든 로딩 표시와 문구에 간격을 둔다

현재 Spinner는 flex 상태 영역에서 아이콘과 문구를 공백 문자로만 구분한다. 공통 로딩 행에 명시적인 gap8~12px과 정렬을 적용한다. 아이콘은 줄어들지 않게 하고 긴 문구는 자연스럽게 줄바꿈한다. 영역 로딩·목록 로딩·인라인 로딩·버튼 로딩을 구분하되 간격 규칙은 공유한다. 로딩 문구를 이중으로 읽거나 버튼 폭이 바뀌어 주변이 흔들리지 않게 확인한다.

### UIREF17 — 라디오는 테두리와 안쪽 점이 구분돼야 한다

현재 radio가 check 스타일을 조합하면서 checked의 청색 배경을 공유해 전체가 파란 점처럼 보인다. 라디오 바깥 원은 약20px의 테두리와 흰 표면을 유지하고, 선택됐을 때 중앙에8~10px 점을 표시한다. 테두리와 점 사이에 흰 여백이 분명히 보여야 한다. 미선택·선택·포커스·비활성/비활성 선택을 모두 확인한다. 기존 Radix RadioGroup의 의미·방향키·label 클릭은 보존한다. 체크박스 checked 배경 규칙이 라디오에 새지 않도록 구조를 정리한다.

### UIREF18 — 검색형 선택 상자의 내부 구역을 나눈다

검색 입력, 결과 목록/빈 결과, 하단 동작을 독립 구역으로 배치한다. 검색 입력의 외곽 포커스 표시가 잘리지 않게 패딩을 두고, 결과와 최소12px 떨어뜨린다. “검색 결과가 없습니다.”는 별도 빈 결과 영역에 적절한 위아래 여백을 둔다. 포커스를 없애거나 outline:none으로 해결하지 않는다. 결과0개/1개/많음·키보드/긴항목·모바일에서 본문과 footer가 붙거나 넘치지 않는지 확인한다.

### UIREF19 — 날짜를 달력에서 고를 수 있는 공통 컨트롤을 제공한다

현재 DateInput은 날짜 형식의 텍스트 입력만 제공한다. 기존 날짜 검증·문자열 값·UTC 변환은 유지하면서 공통 DatePicker와 DateTimePicker를 제공한다. 단순히 native date input을 화면에 하나 추가하는 것으로 끝내지 않는다. 기존 Radix Popover와 날짜 유틸을 활용하고, 별도 UI 프레임워크는 추가하지 않는다.

- DatePicker: 입력+달력 열기 버튼, 선택한 날짜와 오늘 구분, 이전/다음 월, 월/연도 이동, 날짜 선택·지우기·닫기를 제공한다. 입력으로 직접 수정하는 기능도 유지한다. 화면은 yyyy-MM-dd, 외부 값도 기존 날짜 문자열이며 날짜만 값에는 시간대 변환을 하지 않는다.
- DateTimePicker: 달력과 시/분/초·필요한 경우 밀리초 입력을 함께 제공한다. 날짜 선택 때문에 기존 시간/밀리초가 의도 없이 사라지면 안 된다. 팝업의 임시 선택을 확인으로 반영하고 취소/닫기는 확정되지 않은 값을 반영하지 않는다. 표시 시간대 Asia/Seoul/UTC와 서버 UTC 문자열의 기존 변환 함수를 재사용한다. 브라우저 시스템 시간대를 사용해 결과를 바꾸지 않는다.
- 기존 DateInput/DateTimeInput/DateRangeInput 호출부의 값·검증·ref·label·disabled/readOnly/min/max를 보존한다. 날짜/날짜시간/기간은 공통 선택부를 공유하고 검색 기간과 예제에서 재사용한다. 기존 이름을 호환 래퍼로 유지하거나 호출부를 일관되게 전환한다.
- 윤년·월말·연도0001~9999·최소/최대·기간 역전/최대31일·서울 과거 DST 중복/없는 시각의 거부 규칙은 유지한다. Date 생성자의0~99년 보정 같은 함정을 피하고 기존 엄격한 날짜 함수를 사용한다. 달력에서 선택할 수 없게 막힌 날짜를 텍스트 입력으로 우회할 수 없어야 한다.
- 키보드: 달력 안은 방향키로 날짜 이동, Home/End로 주의 시작/끝, PageUp/PageDown으로 월 이동, Enter/Space로 선택한다. Tab 순서·현재 날짜/선택 날짜 접근 가능한 이름, Escape 닫기와 트리거 포커스 복귀를 제공한다. 비활성/읽기 전용은 팝업 조작으로 우회하지 않는다.
- 날짜·시간 예제에 직접 체험할 수 있는 달력과 짧은 사용 안내를 제공한다. 단일 날짜, 초/밀리초 시각, 기간, 제한 범위, 비활성/읽기 전용을 보여주되 화면을 긴 옵션 목록으로 만들지 않는다.
- 360/390px 팝업 열림과 PC의 이동/선택·스크롤/위치·키보드·지우기·값 확정/취소를 확인한다. strict CSP에서 동작해야 하며 인라인 스타일 전면 허용이나 보안 설정 완화는 금지한다.

### 추가 수정 확인 방법

이번 색상/라디오/로딩/검색 빈 결과/달력 열린 모습은 PC와 모바일 실제 화면으로 확인한다. 비교 대상과 결과 이미지를 외부 작업 공간에 보관한다. 날짜 변경은 기존 foundation 날짜 회귀와 키보드·폼 연결을 검사하고, 공통 로딩과 선택 스타일 변경은 관련 목록/폼/버튼 예제도 확인한다. 타입·lint·형식·local/prod 빌드를 적용하고 이전 API 생성 기본 경로 수정은 보존한다. 값/인증/데이터 계층은 바꾸지 않는다. 완료 후 기존 리뷰 채팅에서 공통 컨트롤·날짜 정확성·접근성·CSP를 독립 검토한다.
