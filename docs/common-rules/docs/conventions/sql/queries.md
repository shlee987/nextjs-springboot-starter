# SQL 구성과 변경

## 조회와 JOIN

필요 컬럼을 명시하고 명시적 JOIN으로 관계와 조건 소속을 드러낸다. NULL 비교·집계 단위·중복 행 원인을 확인한다. DISTINCT로 JOIN 오류를 숨기거나 읽기 쉬운 쿼리를 불필요한 서브쿼리로 감싸지 않는다.

## 표현과 내장 함수

- 대상 DB의 내장 함수로 목적을 명확하고 간결하게 표현할 수 있으면 우선 사용한다. 같은 처리를 불필요한 분기·수식·서브쿼리로 풀어 쓰지 않으며, 과도한 함수 중첩은 피한다.
- 분기·NULL 처리·문자열·날짜 가공·변환·계산 등 SQL 표현 전반에 적용한다. 변경 시 NULL 처리·반환 타입·결과의 의미를 유지한다.

## 정렬과 페이징

결과 순서가 필요한 경우 ORDER BY를 명시하고 페이징에는 동률을 구분하는 안정적인 정렬을 사용한다. 구문·함수는 실제 DB 방언을 따른다.

## INSERT·UPDATE·DELETE

대상 범위와 변경 컬럼을 명시한다. 필수 조건 누락이나 빈 입력 때문에 전체 수정·삭제로 확대되지 않게 한다. 의도된 전체 변경은 별도 계약으로 구분한다.

## 복잡도

CTE·서브쿼리는 의미 있는 단계가 있을 때 사용한다. N+1과 불필요한 전체 조회를 피한다.

## 변경 검증

- `../common/changes.md`의 검증 기준에 따라 변경한 SQL의 문법·파라미터 바인딩·결과 매핑과 관련 동작을 확인한다. MyBatis 동적 조건은 `mybatis.md`의 확인 범위를 적용한다.
- 공통 SQL 조각 변경은 실제 참조 쿼리까지 확인한다. 실행 계획은 성능 문제나 영향이 큰 변경에서만 확인하며 모든 쿼리를 매번 검사하지 않는다.
- 실제 DB와 기존 테스트를 활용한다. 문법 검사만으로 결과 정확성을 보장했다고 보고하지 않으며 실행한 검사와 미확인 부분을 구분한다.
