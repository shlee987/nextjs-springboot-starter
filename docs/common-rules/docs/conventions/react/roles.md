# React 역할 패턴

함수 분리·오류 처리 변경 시 부모 파일이 지정한 공통 문서를 적용한다.

## 함수 역할

- 컴포넌트 내부의 이름 있는 이벤트 처리 함수는 handleX, 이벤트 콜백 props는 onX로 구분한다.
- 상태 setter는 setX로 상태 이름과 짝을 맞춘다. 저장 요청이나 업무 동작을 상태 setter처럼 이름 짓지 않는다.
- getX는 이미 가진 데이터의 조회, fetchX는 외부 조회에 사용한다. 이 구분은 이 세트의 선택이며 React 필수 문법이 아니다.
- 계산·변환·저장은 calculateTotal/formatDate/saveItem처럼 실제 동작을 드러낸다.
- 이벤트 처리는 입력·이벤트 반응과 화면 동작을 연결한다. 복잡한 계산이나 외부 연동에 독립된 책임이 있으면 분리한다.
- 짧은 상태 변경이나 콜백 전달을 위해 이름 있는 중간 함수를 강제로 만들지 않는다.
- 재사용 Hook은 use로 시작하고 React Hook을 사용하는 로직을 담는다. 일반 유틸리티에는 use 접두사를 붙이지 않는다.
- Hook 호출은 해당 React API의 호출 규칙을 따른다. 역할 구분을 이유로 일반 함수에 Hook 호출을 옮기지 않는다.

## 컴포넌트·Hook

- 여러 이벤트가 있으면 handleSaveClick/onSave처럼 대상·의도를 구분한다. DOM 이벤트를 그대로 전달할지 필요한 값만 전달할지 콜백 타입으로 명확히 정한다.
- 컴포넌트는 UI 책임으로 묶는다. 독립된 UI·상태 경계가 있을 때 분리하고 JSX 길이만으로 나누지 않는다. 다른 컴포넌트를 렌더 함수 안에 새 타입으로 선언하지 않는다.
- Hook은 상태·구독 등 React 로직을 응집해 이름과 반환 계약으로 드러낼 때 분리한다. React와 무관한 계산·변환은 일반 함수로 둔다. 생명주기만 감싼 useMount 같은 추상화를 기본으로 만들지 않는다.
- props와 state를 직접 변경하지 않는다. 변경은 해당 상태 소유자의 setter·명시된 동작으로 수행한다.
- 기존 props/state로 계산되는 값은 렌더 중 계산한다. 계산 결과를 별도 state와 Effect로 동기화하지 않는다.
- 클릭·제출로 발생한 작업은 이벤트 경로에서 수행한다. Effect는 외부 시스템 동기화에 사용하고 구독·타이머 등은 정리한다.
- Hook 의존성 규칙을 숨기거나 무시하지 않는다. 데이터 조회는 기존 프레임워크·요청 계층을 우선하고 비동기 응답 순서·언마운트에 따른 오래된 결과 반영을 방지한다.
- 목록 key는 항목의 안정적인 식별자를 사용한다. 재정렬·추가·삭제 가능한 목록에 인덱스나 렌더마다 바뀌는 값을 사용하지 않는다.
- memo/useMemo/useCallback은 실제 성능 필요나 참조 안정성 계약이 있을 때 사용한다.
