# 설정·상수·상태 값

- 값의 변경 이유와 역할에 따라 배치한다. 기존 설정·상수·타입 정의를 우선 활용한다.
- 환경·프로파일·운영 조건에 따라 달라지는 값은 기존 설정 체계로 관리한다. 실제 빌드 결과·기능 포함 여부를 결정하는 값은 빌드 설정에 둔다. 빌드 시 주입과 실행 시 설정을 구분하고 같은 값을 여러 곳에 중복 정의하지 않는다.
- 코드에서 고정된 의미를 가진 값은 상수, 제한된 상태·종류는 enum 또는 해당 언어의 동등한 제한 타입으로 표현한다. 허용값의 타입과 실제 선택값의 설정은 함께 사용할 수 있다.
- 한 클래스·모듈에서만 쓰는 상수는 그 안에 둔다. 여러 곳에서 같은 의미로 공유할 필요가 있을 때만 역할별 상수 클래스·모듈을 만든다. 무관한 값을 하나의 Constants에 모으지 않는다.
- 함수에서만 쓰는 자명한 값은 로컬에 유지한다. 모든 리터럴을 상수나 설정으로 추출하지 않고, 의미 표현·일관된 변경에 이점이 있을 때 이름을 부여한다.
- 코드 곳곳에서 프로파일 이름을 비교해 환경별 값을 선택하지 않는다. 값 차이는 설정으로, 실제 구현 차이는 프로젝트의 기존 조건부 구성 방식으로 처리한다.
- 비밀값은 코드·공유 상수·저장소의 설정 파일에 직접 넣지 않고 기존 비밀정보 주입 방식을 따른다. 새 설정은 필요한 기본값·필수 여부·허용 범위를 정하되 근거 없는 fallback을 추가하지 않는다.
