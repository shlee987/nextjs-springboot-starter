# UI 적용·스타일과 공통화

CSS·SCSS·CSS Modules·Bootstrap·Tailwind 등에서 UI를 개발에 적용할 때 따른다. 특정 도구나 폴더 구조를 강제하지 않는다.

- **재사용:** 해당 UI의 기존 공통 컴포넌트·클래스·테마 값과 상속을 우선 활용한다. 이미 적용되는 속성을 개별 요소에 다시 지정하지 않고, 같은 역할·디자인의 반복 스타일은 기존 공통 정의에서 관리한다. 값이 우연히 같다는 이유만으로 다른 역할을 묶거나, 모든 일회성 값을 공통화하지 않는다.
- **개별 지정:** 공통 정의와 다른 실제 요구만 지정한다. 고정 디자인은 기존 스타일 정의 방식으로 관리하고, 인라인 스타일은 실행 중 계산되는 값 등 필요한 경우에 사용한다. 기존 유틸리티 클래스 활용도 공통 정의 재사용이며 이를 다시 감싸는 클래스를 만들 필요는 없다. 같은 속성을 충돌하는 클래스·인라인 선언·불필요한 !important로 겹쳐 덮어쓰지 않는다.
- **클래스 구조:** 새 클래스는 UI 역할을 나타내고 기본·하위 요소·변형을 구분한다. 기존 명명·범위 지정 방식을 따르며, 일반 CSS에 별도 관례가 없으면 BEM(block__element--modifier)을 사용한다. 공통 UI는 공유 범위, 화면 고유 스타일은 해당 화면·컴포넌트 범위에 둔다. 기존 역할의 정의를 우선 확장하고 불필요한 파일 분리·깊은 선택자 중첩·프레임워크 클래스와의 이름 충돌을 피한다.
- **개선 범위:** 현재 작업에 직접 관련된 UI와 스타일에서 중복 선언·불필요한 덮어쓰기를 줄이고 기존의 잘못된 패턴을 새 코드에 복제하지 않는다. 기존 표현·상태를 유지하고 공유 정의 변경 시 기존 사용처의 영향을 확인한다. 무관한 사용처까지 수정하지 않으며 전체 스타일 정리·일괄 교체는 사용자의 명시적 요청이 있을 때만 수행한다. 실제 대체 정의를 마련하고 기존 정의를 유지해야 한다면 기존 정의에 대체 대상과 교체 조건을 한국어 주석으로 남긴다. 교체 안내가 있으면 신규 사용은 대체 정의를 우선하고, 기존 사용처는 현재 작업 범위에서 조건을 확인한 뒤 교체한다.

교체 안내 예시:

```css
/*
 * 대체 스타일: .form-label
 * 해당 UI 수정 시 표현·상태가 동일한 경우 교체 권장.
 * 전체 정리 시 남은 사용처를 확인한 뒤 이 정의를 제거한다.
 */
```

## 기본 동작과 표시 검증

- 동작은 button, 이동은 링크 등 목적에 맞는 HTML 요소와 기존 UI 컴포넌트를 사용한다. 입력은 label과 연결하고 아이콘만 있는 조작 요소에도 목적을 알 수 있는 이름을 제공한다. 기존 키보드 조작·포커스 표시를 유지하며 네이티브 의미로 표현할 수 있는 경우 불필요한 ARIA나 별도 이벤트 구현을 추가하지 않는다.
- 변경한 UI는 가능한 실행 환경에서 관련 화면·상태를 확인한다. 긴 문구·좁은 화면에서 잘림·겹침을 확인하고, 프로젝트가 지원하는 테마와 변경한 조작 요소의 키보드·포커스 동작을 점검한다. 변경 영향이 없는 화면까지 일괄 검사하지 않으며, 실행 확인이 불가능하면 코드로 확인한 범위와 미확인 부분을 알린다.
