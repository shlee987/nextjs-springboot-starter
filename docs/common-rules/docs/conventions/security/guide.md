# 보안 초기 설정과 변경 지침

이 문서는 프런트엔드·백엔드·배치·DB·인프라·CI/CD를 처음 구성하는 AI가 참조하는 공통 지침이다. 특정 프로젝트나 클라우드, 프레임워크, 배포 도구를 전제하지 않는다.

## 읽는 순서

1. 공통 AGENTS.md의 조건에 따라 이 파일을 읽는다.
2. `references.md`에서 공통 기준과 실제 기술에 해당하는 공식 문서를 선택한다.
3. `setup-checklist.md`에 따라 설계·설정·검증한다.

기존 프로젝트의 일부 변경에서는 관련 영역만 검토한다. 프로젝트 전체 초기 설정 체크리스트를 매번 강제하지 않는다.

## 적용 원칙

- 사용자 요청과 상위 지침, 대상 프로젝트의 AGENTS.md 및 명시된 계약을 우선한다. 충돌은 숨기지 않고 설명한다.
- 먼저 기술 스택과 버전, 배포 방식, 인증 방식, 데이터 종류, 외부 연동, 서비스 간 통신을 파악한다. 코드와 설정에서 확인 가능한 것은 직접 확인한다.
- ASVS를 애플리케이션 요구사항 기준으로, OWASP Cheat Sheets를 구현 지침으로 사용한다. 서버·DB·클라우드는 CIS 및 해당 제품의 공식 보안 문서로 보충한다.
- 참조 URL의 현재 내용을 확인한다. 최신 문서의 설정을 구버전 프로젝트에 그대로 복사하지 않는다. 프로젝트 버전과 지원 종료 여부를 함께 확인한다.
- 문서 전체를 무조건 읽지 말고 적용 대상별로 필요한 부분을 읽는다. 열람할 수 없으면 확인하지 못한 범위를 밝히고 최신 내용을 확인했다고 주장하지 않는다.
- 개발을 시작하기 전에 보안 요구사항과 라이브러리 호환성을 확인한다. 정상 기능 때문에 보안을 광범위하게 해제하는 설계를 기본값으로 삼지 않는다.
- 프런트의 화면 숨김이나 입력 치환만으로 접근 통제·XSS 대응을 완료했다고 판단하지 않는다. 서버 검증, 출력 문맥에 맞는 처리, 브라우저 정책을 함께 설계한다.
- 로컬·개발·운영의 설정을 구분한다. 편의를 위한 로컬 예외가 배포 환경으로 전파되지 않게 한다.
- 실제 비밀번호·토큰·개인키·복호화키는 소스 및 배포 산출물에 내장하지 않는다. 암호문과 복호화키를 함께 제공하는 방식은 비밀 보호의 완료로 판단하지 않는다.
- 최소 권한과 명시적 허용을 기본으로 한다. CSP·CORS·방화벽·인증 예외를 포괄적으로 허용하기 전에 필요한 기능과 범위를 확인한다.
- 공통 CI/CD 보안 기준을 먼저 적용하고 도구별 문서로 구현한다. Jenkins, Azure DevOps, GitHub Actions, GitLab CI, AWS 등 특정 제품만을 공통 기준으로 삼지 않는다.
- 자동 검사만으로 완료를 선언하지 않는다. 실제 권한 검사, 보안 헤더, 비밀값 주입, 실패 동작, 정상 기능을 확인한다.
- 오탐·위험 허용·적용 제외·수정 완료를 구분한다. 위험 허용은 취약점 제거가 아니다. 정보 등급 또는 빌드 결과물이라는 이유만으로 전체 검사를 제외하지 않는다.
- 예외는 규칙·경로·환경·사유를 최소 범위로 기록하고 재검토 조건을 둔다. 새로운 경로에 기존 예외를 자동 확대하지 않는다.

## 작업 결과에 남길 내용

기술 및 버전, 적용한 기준과 공식 URL, 기준 버전과 확인일, 실제 변경 위치, 검증 결과, 미적용 사유와 남은 위험을 간결하게 남긴다. 비밀값 자체는 기록하지 않는다.

문서 URL은 최신 지침을 확인하기 위한 진입점이다. 문서 갱신이 프로젝트에 자동 적용되는 것은 아니다. 프로젝트 착수·주요 버전 변경·인증 또는 배포 구조 변경·보안 권고 발생 시 재확인한다.

이 문서는 공통 AGENTS.md에서 조건부로 참조한다. 대상 프로젝트는 공통 진입점을 연결하고 같은 상대 경로 구조를 유지한다.
