`FileUpload`의 `upload({file, signal, onProgress})`는 서버 저장 응답까지 기다리는 Promise를 반환해야 합니다. 진행 콜백은 실제 전송 계층에서 받은 loaded/total만 전달합니다. 100%는 전송 완료이며 Promise가 resolve하기 전에는 서버 저장 처리 중입니다. 공통 UI가 임의 진행률이나 타이머 성공을 생성하지 않습니다. `actionKey`는 같은 업로드 작업에서 고정하며 UIOPT09의 동기 잠금·공유 진행 상태를 사용합니다. 취소 시 실제 Promise 종료까지 잠금을 유지합니다. 취소된 전송은 서버에서 이미 저장됐을 수 있으므로 내 목록 확인 후 재시도하도록 안내합니다. 선택 제거는 서버 삭제가 아닙니다.

현재는 FileUpload만 인증 세대별 key로 다시 마운트하고 본인 목록 QueryKey와 페이지를 세대별로 분리합니다. PermissionGuard는 유지해 익명401 뒤 재마운트·인증 확인 반복을 막습니다. 클라이언트의 확장자/MIME/크기 검사는 사용자 안내이며 내용 검증·소유권·용량 통제는 서버 책임입니다.
